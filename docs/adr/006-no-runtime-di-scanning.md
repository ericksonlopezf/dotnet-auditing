# ADR-006: No Runtime DI Scanning

**Status**: Accepted

### Context
`services.AddHandlersFromAssembly(typeof(MyAssembly))` scans the assembly at runtime using reflection to find all `ICommandHandler<,>` implementations. This is a common pattern but hostile to AOT and trimming.

### Decision
Handler registration is entirely generated by the source generator. The generated `AddEricksonLopezMediator()` extension method contains explicit, concrete calls like `services.AddTransient<CreateOrderHandler>()`.

### Why
- Assembly scanning at startup is O(n) where n = types in assembly
- Assembly scanning is incompatible with trimming (trimmer removes types not referenced by IL)
- Assembly scanning is incompatible with AOT (requires reflection over all types)
- Generated registration is O(1) in startup time

### Consequences
+ Zero startup cost for handler registration
+ Fully trim-safe
+ Fully AOT-safe
- Handlers not included in compilation are not registered (correct behavior)
- Multi-assembly scenarios require explicit configuration (see ADR-012)
