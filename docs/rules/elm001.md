# ELM001: Handler Not Found

| Property | Value |
|---|---|
| **Rule ID** | `ELM001` |
| **Category** | `EricksonLopez.Mediator.Design` |
| **Severity** | `Error` |
| **Enabled by Default** | `true` |
| **Applies to** | Types implementing `ICommand<TResponse>` or `IQuery<TResponse>` |

---

## 🎯 Rule Description

`EricksonLopez.Mediator` uses compile-time source generation and static dispatch tables. When a command (`ICommand<TResponse>`) or query (`IQuery<TResponse>`) is defined in the compilation or referenced in dispatch calls without a matching concrete implementation of `ICommandHandler<TCommand, TResponse>` or `IQueryHandler<TQuery, TResponse>`, `ELM001` is emitted at compile time.

This guarantees at compile time that no unhandled in-process messages exist in the system, completely eliminating runtime `InvalidOperationException` crashes common in reflection-based mediators.

---

## ❌ Violation Example

```csharp
public readonly record struct CreateOrderCommand(Guid OrderId, decimal Total) : ICommand<Result<Guid>>;

// Violation: No class implements ICommandHandler<CreateOrderCommand, Result<Guid>>
```

**Compiler Output:**
> `error ELM001: No handler found for MyApp.Orders.CreateOrderCommand`

---

## ✅ Compliant Example

```csharp
public readonly record struct CreateOrderCommand(Guid OrderId, decimal Total) : ICommand<Result<Guid>>;

public sealed class CreateOrderCommandHandler : ICommandHandler<CreateOrderCommand, Result<Guid>>
{
    public ValueTask<Result<Guid>> Handle(CreateOrderCommand command, CancellationToken cancellationToken)
    {
        // Business logic execution
        return ValueTask.FromResult(Result<Guid>.Success(command.OrderId));
    }
}
```

---

## 🛠️ Multi-Assembly Handler Discovery

If the handler is located in a referenced assembly, use `[assembly: DiscoverHandlers(typeof(MarkerType))]` in your startup project to instruct the Roslyn generator to include external assembly syntax trees in compile-time handler discovery.
