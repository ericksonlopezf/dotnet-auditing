# ELM002: Multiple Command Handlers Found

| Property | Value |
|---|---|
| **Rule ID** | `ELM002` |
| **Category** | `EricksonLopez.Mediator.Design` |
| **Severity** | `Error` |
| **Enabled by Default** | `true` |
| **Applies to** | Types implementing `ICommand<TResponse>` |

---

## 🎯 Rule Description

Commands represent state-altering intent in CQRS architectures and must follow strict point-to-point dispatch semantics. Exactly one handler must be responsible for processing a command. 

If multiple classes implement `ICommandHandler<TCommand, TResponse>` for the same command, the Roslyn generator halts compilation with `ELM002` to prevent ambiguous execution paths.

---

## ❌ Violation Example

```csharp
public readonly record struct CancelOrderCommand(Guid OrderId) : ICommand<Result>;

// Handler 1
public sealed class CancelOrderHandlerA : ICommandHandler<CancelOrderCommand, Result>
{
    public ValueTask<Result> Handle(CancelOrderCommand cmd, CancellationToken ct) => ...;
}

// Handler 2 (Violation: Multiple command handlers found for CancelOrderCommand)
public sealed class CancelOrderHandlerB : ICommandHandler<CancelOrderCommand, Result>
{
    public ValueTask<Result> Handle(CancelOrderCommand cmd, CancellationToken ct) => ...;
}
```

---

## ✅ Compliant Example

Consolidate handling logic into a single dedicated handler:

```csharp
public sealed class CancelOrderCommandHandler : ICommandHandler<CancelOrderCommand, Result>
{
    public ValueTask<Result> Handle(CancelOrderCommand command, CancellationToken cancellationToken)
    {
        return ValueTask.FromResult(Result.Success());
    }
}
```
