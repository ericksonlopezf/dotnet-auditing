# ELM003: Multiple Query Handlers Found

| Property | Value |
|---|---|
| **Rule ID** | `ELM003` |
| **Category** | `EricksonLopez.Mediator.Design` |
| **Severity** | `Error` |
| **Enabled by Default** | `true` |
| **Applies to** | Types implementing `IQuery<TResponse>` |

---

## 🎯 Rule Description

Queries represent side-effect-free data retrieval requests in CQRS architectures. Like commands, queries adhere strictly to single-target point-to-point dispatch semantics. 

If multiple classes implement `IQueryHandler<TQuery, TResponse>` for the same query type, compilation is aborted with `ELM003`.

---

## ❌ Violation Example

```csharp
public readonly record struct GetOrderByIdQuery(Guid OrderId) : IQuery<Result<OrderDto>>;

public sealed class DatabaseQueryHandler : IQueryHandler<GetOrderByIdQuery, Result<OrderDto>> { ... }
public sealed class CacheFirstQueryHandler : IQueryHandler<GetOrderByIdQuery, Result<OrderDto>> { ... } // Violation
```

---

## ✅ Compliant Example

Wrap caching or decorator concerns in a pipeline behavior rather than creating competing handler classes:

```csharp
public sealed class GetOrderByIdQueryHandler : IQueryHandler<GetOrderByIdQuery, Result<OrderDto>>
{
    public ValueTask<Result<OrderDto>> Handle(GetOrderByIdQuery query, CancellationToken cancellationToken)
    {
        return ValueTask.FromResult(Result<OrderDto>.Success(new OrderDto(query.OrderId)));
    }
}
```
