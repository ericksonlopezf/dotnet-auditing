# ELM008: Behavior Order Conflict

| Property | Value |
|---|---|
| **Rule ID** | `ELM008` |
| **Category** | `EricksonLopez.Mediator.Design` |
| **Severity** | `Warning` |
| **Enabled by Default** | `true` |
| **Applies to** | `[UseBehavior]` and `[UseGlobalBehavior]` declarations |

---

## 🎯 Rule Description

Emitted when multiple pipeline behaviors configured for a request or notification share the exact same `Order` index. Because execution order among behaviors sharing an order index is non-deterministic, `ELM008` recommends assigning distinct sequential indices.

---

## ❌ Violation Example

```csharp
[UseBehavior(typeof(LoggingBehavior<,>), order: 1)]
[UseBehavior(typeof(ValidationPipelineBehavior<,>), order: 1)] // Warning: Order conflict (Order 1)
public readonly record struct CreateOrderCommand : ICommand<Result>;
```

---

## ✅ Compliant Example

```csharp
[UseBehavior(typeof(LoggingBehavior<,>), order: 1)]
[UseBehavior(typeof(ValidationPipelineBehavior<,>), order: 2)] // Distinct order
public readonly record struct CreateOrderCommand : ICommand<Result>;
```
